Pygame · Bài 3 trên hành trình làm game xây dựngLưới ô (grid) và bắt click chuột

Từ bài này, các bài học sẽ đi thẳng vào game bạn đang làm: một game xây dựng trên lưới ô, quản lý tài nguyên, có HUD đi kèm — lấy cảm hứng từ thể loại game xây dựng/quản lý tài nguyên trên lưới, nhưng là phiên bản gốc, đơn giản hoá, do bạn tự thiết kế (một loại tài nguyên, vài loại công trình, một luật mở khoá, một điều kiện thắng — đúng như bạn đã chọn).

Việc đầu tiên mọi game kiểu này cần: một lưới ô (grid) mà người chơi bấm vào từng ô để xây dựng. Bài này dạy đúng hai kỹ năng lõi đó — vẽ lưới, và biết chính xác ô nào vừa bị bấm.

Mô hình tư duy: tách "dữ liệu" khỏi "hình vẽ"

Đây là khái niệm quan trọng nhất của bài — quan trọng hơn cả cú pháp. Lưới ô trong game của bạn thực chất gồm hai thứ tách biệt:

  1. Dữ liệu (data) — một cấu trúc Python thuần (danh sách lồng danh sách) ghi nhớ ô nào đang có gì. Không liên quan gì tới Pygame cả — đây chỉ là list Python bình thường.
  2. Hình vẽ (rendering) — mỗi frame, bạn đọc dữ liệu đó và vẽ ra màn hình tương ứng, bằng pygame.draw.rect mà bạn đã học ở Bài 1.
Vì sao phải tách ra như vậy Nếu bạn chỉ nghĩ "lưới ô" là 64 hình chữ nhật vẽ sẵn trên màn hình, bạn sẽ bị kẹt ngay khi cần trả lời câu hỏi "ô này đang xây gì?" — vì Pygame không hề nhớ chuyện đó giúp bạn (nhắc lại từ Bài 1: Pygame không tự nhớ gì cả). Khi tách dữ liệu ra thành một list Python riêng, mọi câu hỏi về trạng thái game ("ô (2,3) có trống không?", "đã xây bao nhiêu công trình?") đều trở thành một câu lệnh Python đơn giản trên list đó, tách biệt hoàn toàn khỏi việc vẽ hình.

Bước 1 — Biểu diễn lưới ô bằng dữ liệu

GRID_COLS = 8
GRID_ROWS = 6
TILE_SIZE = 80   # mỗi ô vuông 80x80 pixel

# grid[row][col] = 0 nghĩa là ô trống; sẽ dùng số khác cho "đã xây" ở bài sau
grid = [[0 for _ in range(GRID_COLS)] for _ in range(GRID_ROWS)]

grid bây giờ là một list 6 phần tử (6 hàng), mỗi phần tử lại là một list 8 phần tử (8 cột) — toàn số 0. Đây hoàn toàn là Python thuần, chạy được cả khi không có Pygame. Muốn biết ô ở hàng 2, cột 3 đang chứa gì? Chỉ cần grid[2][3].

Pitfall kinh điển — thứ tự row/col Trong lập trình lưới ô, quy ước gần như luôn là grid[row][col], tức hàng trước, cột sau — ngược với cách bạn hay nghĩ về toạ độ (x, y) (x là cột/ngang, y là hàng/dọc). row tương ứng với y, col tương ứng với x. Lẫn lộn chỗ này là lỗi mới học hay gặp nhất ở bài này — khi debug, luôn tự hỏi: "biến này là toạ độ pixel (x,y) hay chỉ số ô (row,col)?"

Bước 2 — Vẽ lưới từ dữ liệu

def draw_grid(screen, grid):
    for row in range(GRID_ROWS):
        for col in range(GRID_COLS):
            x = col * TILE_SIZE
            y = row * TILE_SIZE
            rect = (x, y, TILE_SIZE, TILE_SIZE)

            if grid[row][col] == 0:
                color = (50, 70, 50)      # ô trống — xanh rêu tối
            else:
                color = (160, 120, 60)    # ô đã xây — nâu đất

            pygame.draw.rect(screen, color, rect)
            pygame.draw.rect(screen, (20, 20, 20), rect, width=2)  # viền ô, width=2 nghĩa là chỉ vẽ viền, không tô đặc

Để ý công thức x = col * TILE_SIZE và y = row * TILE_SIZE — đây chính là cách quy đổi từ "chỉ số ô" sang "toạ độ pixel thật trên màn hình". Ô (row=0, col=0) nằm ở pixel (0, 0); ô (row=1, col=2) nằm ở pixel (2×80, 1×80) = (160, 80).

Tham số thứ 3 của pygame.draw.rect mà bạn chưa thấy ở Bài 1: width=2. Mặc định (không truyền width, hoặc width=0) sẽ tô đặc cả hình. Truyền width=2 nghĩa là chỉ vẽ viền dày 2 pixel, để lại phần giữa trong suốt — dùng để vẽ viền phân cách giữa các ô cho dễ nhìn.

Bước 3 — Quy đổi ngược: pixel chuột → chỉ số ô

Đây là phần mới nhất của bài: biết chuột vừa bấm vào ô nào. Pygame cho bạn biết chuột bấm ở toạ độ pixel nào (qua sự kiện); bạn cần tự quy đổi ngược sang chỉ số ô, bằng đúng phép toán ngược lại với Bước 2: 

def pixel_to_tile(pos):
    x, y = pos
    col = x // TILE_SIZE
    row = y // TILE_SIZE
    return row, col

// là phép chia lấy phần nguyên (floor division) của Python — đúng thứ cần ở đây, vì chỉ số ô luôn là số nguyên. Ví dụ click tại pixel (165, 83) với TILE_SIZE = 80: col = 165 // 80 = 2, row = 83 // 80 = 1 — đúng là ô (row=1, col=2) ở ví dụ trên.

Ghép lại: bắt sự kiện click chuột

import pygame

pygame.init()
screen = pygame.display.set_mode((GRID_COLS * TILE_SIZE, GRID_ROWS * TILE_SIZE))
clock = pygame.time.Clock()
running = True

while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

        elif event.type == pygame.MOUSEBUTTONDOWN:
            row, col = pixel_to_tile(event.pos)
            # chặn trường hợp bấm ngoài lưới (ví dụ cửa sổ rộng hơn lưới)
            if 0 <= row < GRID_ROWS and 0 <= col < GRID_COLS:
                grid[row][col] = 1 if grid[row][col] == 0 else 0  # bật/tắt ô

    screen.fill((20, 20, 25))
    draw_grid(screen, grid)
    pygame.display.flip()
    clock.tick(60)

pygame.quit()

Chú ý event.type == pygame.MOUSEBUTTONDOWN là một sự kiện mới, cùng họ với pygame.QUIT mà bạn đã biết — nó xuất hiện trong hàng đợi pygame.event.get() đúng một lần, ngay khung hình chuột được bấm xuống. event.pos là tuple (x, y) toạ độ pixel của chuột tại thời điểm bấm, tính theo cửa sổ (không phải theo màn hình máy tính).

Vì sao phải kiểm tra 0 <= row < GRID_ROWS Nếu cửa sổ lớn hơn vùng lưới (hoặc người dùng bấm ra ngoài rìa), phép tính ở Bước 3 vẫn trả về một con số — chỉ là con số đó nằm ngoài phạm vi list grid. Truy cập grid[10][3] khi grid chỉ có 6 hàng sẽ ném lỗi IndexError. Luôn kiểm tra biên trước khi đọc/ghi vào grid bằng chỉ số tính được từ chuột.

Nâng cấp nhỏ: tô sáng ô đang hover chuột

Khác với click (chỉ xảy ra một lần, bắt qua event), việc "chuột đang ở đâu ngay bây giờ" cần hỏi mỗi frame, dùng pygame.mouse.get_pos() — hàm này không phải event, mà là một hàm bạn chủ động gọi bất cứ lúc nào để lấy vị trí chuột hiện tại: 

# Đặt trong phần Draw của loop, SAU khi vẽ grid, TRƯỚC khi flip
hover_row, hover_col = pixel_to_tile(pygame.mouse.get_pos())
if 0 <= hover_row < GRID_ROWS and 0 <= hover_col < GRID_COLS:
    hx, hy = hover_col * TILE_SIZE, hover_row * TILE_SIZE
    pygame.draw.rect(screen, (255, 255, 255), (hx, hy, TILE_SIZE, TILE_SIZE), width=3)

Đây chính là cùng một hàm pixel_to_tile bạn viết ở Bước 3, chỉ khác nguồn toạ độ: lần này lấy từ pygame.mouse.get_pos() (vị trí hiện tại) thay vì từ event.pos (vị trí lúc click). Việc tái dùng hàm này chính là lý do bạn nên viết nó thành một hàm riêng ngay từ đầu, thay vì viết phép tính trực tiếp ngay tại chỗ bắt event.

Thử tự tay làm

  1. Viết đủ code ở trên (data, draw_grid, pixel_to_tile, vòng lặp chính). Chạy thử, bấm vào vài ô khác nhau, xác nhận đúng ô bạn bấm đổi màu, không phải ô bên cạnh.
  2. Thêm phần tô sáng viền trắng theo ô đang hover (Nâng cấp nhỏ ở trên). Di chuyển chuột quanh lưới, xác nhận viền trắng đi theo đúng ô chuột đang trỏ vào.
  3. Dùng Bài 2 (vẽ chữ) để hiện số ô đã "xây" (đếm số ô bằng 1 trong grid) ở góc màn hình — đây chính là mảnh ghép đầu tiên nối Bài 2 và Bài 3 lại với nhau, sẽ dùng trực tiếp cho HUD thật ở bài sau.
  4. Thử nghiệm có chủ đích: tạm thời xoá điều kiện kiểm tra biên (0 <= row < GRID_ROWS...), rồi bấm chuột ra ngoài vùng lưới (nếu cửa sổ bạn có khoảng trống). Quan sát lỗi IndexError hiện ra, đọc kỹ dòng traceback, rồi thêm lại điều kiện kiểm tra biên.

Khác biệt chính giữa bắt sự kiện pygame.MOUSEBUTTONDOWN và gọi pygame.mouse.get_pos() là gì?

Nếu ô bị đổi màu sai vị trí so với chỗ bạn bấm, gần như chắc chắn là lỗi lẫn row/col hoặc x/y ở đâu đó — cứ dán code lên hỏi mình, đừng đoán mò quá lâu.

Nguồn tham khảo chính cho bài này:
  • pygame.event — tài liệu API chính thức, xem phần MOUSEBUTTONDOWN/MOUSEBUTTONUP.
  • pygame.mouse — tài liệu API chính thức, xem get_pos().
  • pygame.draw.rect — tham số width để vẽ viền thay vì tô đặc.
