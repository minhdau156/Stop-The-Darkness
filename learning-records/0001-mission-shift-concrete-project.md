# Mission shifted from generic HUD practice to a concrete game, deliberately scoped down

The user found a reference game (browser tile-based building/resource-management game) and wants
to build an original game with the same core mechanic for their school project, due in 3 weeks.
When asked, they explicitly chose the **simplified scope** (one resource, a few buildings, one
unlock rule, one win condition) over trying to match the reference game's full depth.

This matters for future sessions: don't drift the project back toward richer mechanics
(multiple resources, full adjacency webs, extended modes) unless the user asks — that was a
considered trade-off against a hard deadline, not an assumption to second-guess. See
[[MISSION.md]] for the updated success criteria. Lesson sequencing from here on should target
this specific game: grid rendering + mouse picking next, then resource/HUD state, then a
build-menu UI, then one unlock rule, then a minimal win screen.
